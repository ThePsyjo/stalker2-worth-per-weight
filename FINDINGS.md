# Worth-per-weight mod for STALKER 2 — feasibility (2026-10-19, game 2.0.6, UE 5.5.4)

## Data: confirmed
- Item `Cost` and `Weight` are in `Stalker2/Content/GameLite/GameData/ItemPrototypes.cfg.bin` inside
  `Content/Paks/pakchunk0-Windows.pak` (pak V11, Oodle, index NOT encrypted).
- `.cfg.bin` is decodable with `tools/bin2cfg.py` (joric, https://github.com/joric/stalker). Values inherit via `refkey`.
- `tools/build.py` resolves inheritance; output list in `build/ratings.csv`.
- DLC items live in pakchunk101/102/104 `DLCGameData/*/ItemPrototypes.cfg.bin` (not yet included).
- Trader buy price = Cost x BuyModifier (0.3-0.5 per trader, `TradePrototypes.cfg.bin`) x durability. Ranking by Cost/kg stays valid; absolute ₽ does not.

## Text: confirmed
- English strings: `Stalker2/Content/Localization/Game/en/Game.locres` (locres v3, namespace `ST_S2BaseGameLocalization`, 82857 keys).
- Item names: `sid_items_<SID or LocalizationSID>_name`, descriptions `..._description`. `tools/locres.py` reads it.
- 450 item SIDs map directly to a name key; the rest are NPC variants / other key schemes (to investigate).

## Approaches
1. **Static locres mod (recommended first)**: generate Game.locres with "<name> · 1890/kg" (or a line in the description),
   pack as `~mods/zzz_WorthPerWeight_P.pak` with repak. No runtime code, works on Proton.
   Cons: base price only (ignores durability/trader), replaces whole locres per language -> conflicts with other text mods,
   must regenerate per game patch (ship the generator).
2. **UE4SS Lua runtime mod**: hook inventory tooltip widget, compute live value/kg. Needs RE-UE4SS experimental +
   unofficial 2.0 fix (Nexus 2341). Widget class names unknown -> requires live object dump. Fragile across patches.
3. **Zone Kit (official SDK) widget edit**: edit tooltip WBP and cook. ~700 GB, Windows/Epic. Heaviest.

## Tools
- repak built at scratchpad (`cargo install --git https://github.com/trumank/repak repak_cli`).
- Existing S2AE (Achievements Enabler, winmm.dll proxy) installed in Binaries/Win64.

## 2026-10-20 — Workshop loading
- A plain pak with a replaced Game.locres works from `Content/Paks/~mods` but NOT from a Workshop item:
  the game mounts Workshop mods after localization is loaded.
- Zone Kit mods override texts via `/Script/Stalker2.ModLocalizationDatabaseDataAsset` in a package named
  `Autogenerated_<10 digits>_LocalizationDatabase` (exe string `_LocalizationDatabase`).
  Export (unversioned): TMap<FString key, struct{TMap<ELocalizationLanguage (FName), FString>}>; language FName
  indices 0..17 = alphabetical enum names (Arabic .. Ukrainian).
- Workshop layout: `Windows/{OverrideContent,NewContent}/Windows/Stalker2/Mods/<Mod>/Content/Paks/Windows/<Mod>Stalker2-Windows-<Part>.{pak,utoc,ucas}`
  + `Manifest_UFSFiles_Win64.txt`. NewContent pak (mount `../../../Stalker2/Mods/<Mod>/`) holds `<Mod>.uplugin` + `AssetRegistry.bin`.
- IoStore container id = CityHash64(UTF-16LE lowercase "<Mod>Stalker2-Windows"); AssetRegistry name batch hashes = CityHash64 v1.1 of lowercase name.
- retoc (`cargo install --locked`) round-trips Zone Kit containers legacy<->zen byte-identically for these assets.
- Game log (`compatdata/1643320/.../Stalker2/Saved/Logs/Stalker2.log`) does not record mod mounting.

## 2026-10-20 evening — why the first Zone Kit-style build showed nothing
- TrueGunNames does override existing keys (its Mosin rename fails only because it edits `sid_items_GunMosina_SP_name`,
  while the rifle uses LocalizationSID `myriflepack_GunThreeLine_SP`).
- Diagnostic build (cfg patches -> new `WPW_*` keys) showed raw `sid_items_WPW_*` names: cfg patches from the Override
  .pak load, the database package in the utoc did not.
- Cause (assumed, fix pending in-game confirmation): retoc to-zen hardcodes the utoc mount point `../../../`; Zone Kit uses the
  asset folder (`../../../Stalker2/Content/`, `../../../Stalker2/Mods/<Mod>/Content/`). The game appears to derive the package
  path from the file path relative to the mount point. Fixed via tools/retoc-zonekit.patch (RETOC_TOC_MOUNT_POINT).
- Working mods: BackpacksPack (DB in OverrideContent only, new keys), DecoupledRanks (DB in both containers, LocalizationSID patches).
- ROOT CAUSE (found by diffing container headers): Zone Kit OverrideContent containers carry package redirects
  `/Game/<name>` -> `/<Mod>/<name>` (FMappedName type Container). The game locates the database by file path (/Game/...)
  and only reaches the /<Mod>/ package through that redirect. retoc to-zen writes none (and defaults the redirect name
  type to Package); tools/retoc-zonekit.patch adds RETOC_PACKAGE_REDIRECTS and fixes the type. Header now byte-identical to Zone Kit's.

## Known issues (2026-10-20)
- Does not stack with "True Gun Names" (Workshop 3814035521): our cfg patches point weapons at `WPW_*` keys, so TGN's
  overrides of the original `sid_items_<SID>_name` keys are no longer shown. Overriding the original keys instead
  would make the two mods fight over the same keys (last loaded wins). Real stacking would need the rating built on
  top of the other mod's names. To explore.
- `--newline` breaks the spacing in the upgrade/repair item list; single-line is the default.
- Mod text databases DO override existing keys (TGN works; its Mosin rename fails only because it edits
  `sid_items_GunMosina_SP_name` while the rifle uses LocalizationSID `myriflepack_GunThreeLine_SP`).

## 2026-10-25 — dynamic tooltip mod (Blueprint, no Zone Kit) — WORKS in-game
- Prototype with dev-only UE4SS (build 1028 + Nexus 2341 fix v1.2; ExecuteInGameThread unusable because the fix
  disables the EngineTick hook): tooltip widget `W_ItemInfo_C` (class `/Script/Stalker2.ItemInfo`, no UFUNCTIONs).
  Fields `Price`, `Weight`, `OneItemWeight` are `W_Text_C` (`TextWidget`); the shown text is the child CommonTextBlock
  `CommonTextObj` (TextWidget::GetText returns a stale default). The game rewrites Price on every hover.
- Zone Kit script entry point: Blueprint subclass of `/Script/Stalker2.ModWorldSubsystem` (events OnWorldBeginPlay,
  OnTick + SetTickEnabled), registered by `Autogenerated_<n>_WorldSubsystemData` = `/Script/Engine.ModWorldSubsystemDataAsset`
  { TArray<FString> ModWorldSubsystems = "/<Mod>/<BP>.<BP>_C" } in OverrideContent (redirected like the text database).
- Stock UE 5.5.4 Linux works: stub classes with the game's names; BlueprintReadOnly on stub properties is editor-only,
  cooked Blueprints resolve properties by name at runtime. Linux editor has no Windows cooker; cooking for Linux is fine.
- UE4SS UHT header generator crashes on 2.0.6 (USceneComponent::StaticClass null); CXX dump + usmap work.
