# Worth per Weight — S.T.A.L.K.E.R. 2 mod

Shows each item's value per kilogram right next to its price in every item tooltip (inventory, traders, stashes),
e.g. `45k/kg · 312750 ₭`. It uses the price the tooltip actually shows, so upgrades, durability and items from
other mods are covered. Item names are not touched (compatible with renaming mods such as True Gun Names).

- Steam Workshop: https://steamcommunity.com/sharedfiles/filedetails/?id=3823156532
- Values below 500 show as `<1k/kg`.

## Building

```sh
make tools                     # repak + patched retoc into .bin/ (needs cargo, git)
make UE_ROOT=/path/to/UE GAME="/path/to/S.T.A.L.K.E.R. 2 Heart of Chornobyl"   # Blueprint + Workshop folder
make install-local             # test: copy over your local Workshop download
make upload STEAM_USER=<name> NOTE="change note"
make preview                   # regenerate workshop/preview.jpg from the game's font
```

The individual steps behind those targets:


Requirements: Python 3, an installed copy of the game, and two Rust tools in `.bin/` (or on `PATH`):

```sh
# repak (pak files)
cargo install --root . --git https://github.com/trumank/repak repak_cli && mv bin/repak .bin/
# retoc (IoStore containers), patched for Zone Kit compatibility
git clone https://github.com/trumank/retoc /tmp/retoc && cd /tmp/retoc && git checkout 885a8da \
  && git apply /path/to/this/repo/tools/retoc-zonekit.patch && cargo build --locked --release -p retoc_cli \
  && cp target/release/retoc /path/to/this/repo/.bin/
```

The Blueprint is built with a stock **Unreal Engine 5.5.4 for Linux** (no Zone Kit) and a stub project:

```sh
tools/build_bp.sh /path/to/UnrealEngine   # generates + cooks the Blueprint (ue/Stalker2, headless)
python3 -I tools/build.py --game "/path/to/S.T.A.L.K.E.R. 2 Heart of Chornobyl"
```

`build.py` modes: `--mode dynamic` (default, tooltip Blueprint), `--mode names` (old static rating in item
names: `--format short|full`, `--newline`, `--symbol`), `--mode both`. Output: `build/workshop/` (Workshop content
folder) and `build/ratings.csv`.

Upload with `workshop/upload.sh <steam_username> "change note"` (SteamCMD; updates the item in `workshop/published_id`).

## How it works

Zone Kit mods run Blueprint code through `ModWorldSubsystem` subclasses that the game instantiates from
`Autogenerated_<n>_WorldSubsystemData` assets. This repo builds both without the Zone Kit:

1. `ue/Stalker2` is a stub UE 5.5 project: module `Stalker2` declares the few game classes the Blueprint touches
   (`ModWorldSubsystem`, `ItemInfo`, `TextWidget`) with matching names; module `WPWEng` stands in for the game's
   `/Script/Engine.ModWorldSubsystemDataAsset` (same-length name, byte-patched after cooking).
   Cooked Blueprints bind to classes, functions and properties by name, so the stubs need no real implementation.
2. The `WPWBuild` commandlet (`ue/Stalker2/Source/WPWTools`) generates `/ValuePerKilo/WPW_Init` from C++:
   `OnTick` every 0.1 s → `GetAllWidgetsOfClass(ItemInfo)` → for each visible tooltip read
   `Price/Weight/OneItemWeight.CommonTextObj`, divide, `SetText("45k/kg · 312750")` unless already done.
   `tools/build_bp.sh` builds, runs it and cooks for Linux (unversioned; Blueprints are platform-neutral).
3. `tools/zonekit.py` packs the cooked assets plus Zone Kit boilerplate from `template/` into the
   `NewContent` / `OverrideContent` IoStore containers of the Zone Kit Workshop layout, using retoc patched for
   Zone Kit mount points and container-header package redirects (`tools/retoc-zonekit.patch`).

The older static mode (`--mode names`) decodes `ItemPrototypes.cfg.bin` (`tools/bin2cfg.py`), points items at new
`LocalizationSID`s via cfg patches and ships the renamed texts in a `ModLocalizationDatabaseDataAsset`.
Details and pitfalls are in [FINDINGS.md](FINDINGS.md).
